## Overview

Craft Anything is "See how any website, app or game works, then have AI build your own version" — an open-source, clean-room engine in pure Rust by the ArtCraft/storytold project (`README.md`, MIT OR Apache-2.0). It works in four steps — **Study → Build → Check → Ready** — asking the person question/approval cards when a decision is theirs, and at v0.6.1 each project can set per-kind builder approvals (`README.md` "How it works"; `crates/engine/src/workspace.rs` `ACTION_KINDS`). Two UI modes drive the same engine: **Simple** (a project page with the four steps) and the **Advanced** workbench (functions, pseudo-C, disassembly, hex, call graphs, evidence ledger, agent console). **Clean room** (default) inspects only what a visitor can see — screenshots, visible text, measured layout, colours, fonts — and refuses look-inside tools; **Deep** reads code and files with the built-in engines and Ghidra when installed (`README.md` "Clean room or Deep"; `crates/engine/src/tools/deep.rs`). Building needs a coding agent signed in on your machine — **Claude Code** is supported first (your own unmodified `claude`, your own sign-in); Codex, Copilot, Grok Build, OpenCode, DeepSeek Harness, Aider, Devin and other ACP agents are built, and README says Maki and Devin have been run live (`README.md` "AI"; `docs/grok.md`, `docs/codex.md`). **Status: early alpha** — website rebuilds with three-width checks and game rebuilds in Unity/Unreal/Godot work today; app/game behaviour checks are partial; some engine tools are tested only against stand-ins (`README.md` Status; `docs/STATUS.md`; `docs/tool-status.md`). Source: GitHub `storytold/craft-anything`.

## Capabilities (verified)

### One tool registry, three surfaces

- **303 engine tools in 17 toolsets** at this tag, generated into `docs/tools.md` by `cargo xtask tools` and kept honest by a test floor (`MIN_TOOLS = 271`, unchanged at v0.6.1; `crates/engine/src/tool_list.rs:7`). Each tool is simultaneously an **MCP tool**, a **CLI command** (`craft-anything-cli <id with dashes>`) and a callable tool for the coding agent; the AI and setup layers add 20 more on top (`rebuild_*` 9, `assets_key_*` 3, `ai_model*` 4, `setup_*` 4), so `craft-anything-cli commands` prints **323**, not 303. Toolsets: `core` 36, `native` 55, `apple` 14, `formats` 36, `managed` (.NET) 8, `android` 14, `java` 6, `adb` 24, `browser` 22, `javascript` 11, `runtime` 14, `frida` 9, `application` 17, `database` 1, `projects` 21, `setup` 9, `build` 6 (`docs/tools.md`). The README's "320 tools (300 in the engine)" and `docs/STATUS.md`'s "300 engine tools (320 with the AI and setup layers')" are both stale — quote 303/323.
- **Results are evidence, not answers**: every result carries confidence, coverage and limitations; big ones come back as a summary and page with `core_evidence_browse`. The discipline rules (predict-then-check, cite evidence ids, absence is not proof) are appended to every guided prompt (`crates/mcp/src/prompts.rs` `DISCIPLINE`).
- **MCP server** (`craft-anything-cli mcp`): stdio JSON-RPC; tools default to Essentials plus enabled toolsets, `--all-tools` lists everything; `--inbox DIR` posts `core_person_ask`/`core_action_approve` cards for the desktop app to answer; `--target <json>` takes desktop target metadata (`apps/craft-anything-cli/src/main.rs` `Mcp`). The list is **filtered by mode**: measured against the installed bundle, Deep `--all-tools` lists **323** tools (303 + the 20 extras) while Clean room `--all-tools` lists **108** — exactly the ids in `crates/engine/src/clean_room.rs` `TOOLS` (`crates/mcp/src/lib.rs` `listed`). On a shared host use **`--restricted`**: it omits and refuses tools that act on the machine or reach the network, with `--allow-web` and `--allow-capture` to turn those classes back on (`crates/mcp/src/lib.rs` `restricted_refusal`). **6 guided prompts**, unchanged at v0.6.1 and confirmed live over `prompts/list` (`crates/mcp/src/prompts.rs` `PROMPTS`).
- **CLI subcommands** (`apps/craft-anything-cli/src/main.rs` `Command`): **12 named** — `mcp`, `setup`, `doctor`, `uninstall`, `commands`, `capabilities`, `triage <path>`, `report [--html] [--out] [--no-evidence]`, `chat`, `rebuild`, `ai`, and the hidden `builder-notes` hook (`--help` shows the first 11) — plus **`Tool(Vec<String>)` pass-through** so every tool id is a subcommand (`core-text-read`, `project-approvals-set`, …). The 12 named subcommands are unchanged at v0.6.1; unknown flags are refused.
- **Rebuild from the terminal** (questions asked in the terminal): `craft-anything-cli rebuild <target|"-" for none> "<request>"` with `--rounds N` (default 2), `--backend`, `--unattended`, `--projects-dir`, `--project-folder` + `--existing edit|start-from`, `--continue-in` + `--resume`, `--deep` / `--clean-room`, `--build-with`, `--generate-assets` (`apps/craft-anything-cli/src/rebuild_cmd.rs`). The flag set is unchanged at v0.6.1, but a `--project-folder` that already holds a project keeps its saved target, settings and stack and treats the request as a follow-up; `--existing`, `--build-with` and `--generate-assets` are refused there (use `--continue-in` or `project-assets-allow` later).

### Study (the inspection engine)

- Its own pure-Rust **decoders, disassembler and decompiler** work without outside programs; Deep mode additionally uses **Ghidra** when installed (`README.md` "Under the hood"). Native programs (ELF/Mach-O/PE), .NET (incl. IL2CPP, bundles), Java (with decompilation), Android (adb, APK/AXML/ARSC signing), Apple (runtime, codesign, CAR), Electron (asar, fuse, runtime), JavaScript/JS bundles, websites (CDP browser automation), firmware, packet captures, databases, game archives — one toolset each (`crates/engine/src/tools/`, `crates/formats/src/`). 217 files under `crates/formats/` changed at this tag (archive/extent hardening, new Unity R16/RG16/RGB9e5 and Unreal float texture decoding; `crates/formats/src/unity_texture.rs`, `crates/formats/src/unreal_texture.rs`; `docs/STATUS.md`).
- **Text sources** are readable outside a build: `core_text_read` takes an absolute path or the active target, reads UTF-8 and BOM'd UTF-16, pages by lines (default 200, max 2,000, 256 KiB a page, 64 MiB a file), counts invalid bytes as U+FFFD, refuses a file with a zero byte in its first 8 KiB as binary, and runs nothing (`crates/engine/src/tools/text_tools.rs`). It is Deep-only because it carries target content.
- External engines are optional and detected: Ghidra, Cutter, rizin, GDB, Frida, adb, jadx, JEB, tshark, apktool and CDP browsers (`crates/engines/src/`; `engines_*` tools in `docs/tools.md`); `craft-anything-cli doctor` checks the install, registrations, engines, AI backends and the MCP server.
- "Just look inside" opens a target for questions without building anything (Deep mode).

### Build, check, refine

- The builder is **your own Claude Code** (first-class). Codex, Copilot (ACP), Grok Build (ACP), OpenCode, DeepSeek Harness, Aider, Devin and plain ACP agents are switchable per backend; **which builder gets the tool server and the approval policy is declared per adapter**, not assumed (`crates/ai/src/cli_agents/grants.rs`): Claude Code, Copilot and Grok get both, Codex and OpenCode get the server without our approvals, DeepSeek Harness gets the server but no checked approval path, Devin gets both only over ACP, and Gemini CLI, Antigravity, Hermes, Maki and Aider get neither. README says only Maki and Devin among the ACP agents have been run live; Codex is still unverified (`README.md` "AI"; `docs/copilot.md`, `docs/opencode.md`, `docs/grok.md`). Craft Anything never sees your account; generated pictures and 3D models are opt-in with your own fal.ai key.
- **Per-project approvals**: seven action kinds, each allow / ask / refuse; unset follows Auto mode (Auto: allow web, commands, outside files; refuse publish, deletes outside, system, other tools. Auto off: ask for all but web). The person loosens from the app or CLI; an agent's `project_approvals_set` may only make a kind stricter (`crates/engine/src/workspace.rs` `ACTION_KINDS`, `Manifest::approval`; `crates/engine/src/tools/project_tools.rs`).
- **Checks**: websites are compared at three screen widths; games run the generated program's own `--self-test` against `checks/round-N/self-test.json`; app runs are compared; each round writes into `checks/` and the agent refines what doesn't match (`README.md` Status; `crates/engine/src/self_test.rs`; `docs/file-formats.md`). A round in which every check passed is kept in `inbox/build-progress.json` (`checked`) and stands while nothing it looked at changes, so a prompt that changes nothing in `app/` does not rebuild and restart (`crates/ai/src/rebuild/kept_check.rs`).
- New projects in Python, Go, .NET, Maven, Gradle and Make are built, tested and launched from one catalogue (`crates/engine/src/toolchains.toml` — 8 toolchains with Rust and Node.js; unchanged at v0.6.1).
- **Plugins**: MCP servers, and WASM components in builds with the `wasm-plugins` option (`crates/engine/src/plugins.rs`; `crates/engines/src/wasm_plugin.rs`).

## Known limitations and not-implemented

Do not assign these at v0.6.1:

- **Only Claude Code is the first-class, verified builder.** Codex, Copilot, Grok Build and the other ACP adapters are built; README says only Maki and Devin among the ACP agents have been run live, and Codex hasn't been verified on a real install (`README.md` "AI", "Status").
- **Approvals are a bar, not a wall.** They decide what the builder may do without asking; a builder allowed to run commands runs with the person's own permissions and could change project records another way. `commands: allow` is Auto mode's default and trusts the builder (`docs/claude-code.md`).
- **An agent cannot loosen approvals**: `project_approvals_set` from MCP or an agent may only make a kind stricter; changing it the other way is the person's job in the app or CLI (`crates/engine/src/tools/project_tools.rs`; `crates/engine/src/tool.rs` `AGENT_ENV`).
- **Not every builder gets the same powers.** Gemini CLI, Antigravity, Hermes, Maki and Aider get neither our tool server nor our approvals; Codex, OpenCode and DeepSeek Harness get the server without our approval decisions; Devin only over ACP (`crates/ai/src/cli_agents/grants.rs`).
- **Grok Build is a build backend only**: chats and questions are refused; the xAI API backend (when `XAI_API_KEY` is set) is separate (`docs/grok.md`).
- **Behaviour checks for apps and games are partial**; website checks are the mature path.
- **Some engine tools are tested only against stand-ins** (`crates/engine/src/tools/standin_tools.rs`; `docs/tool-status.md` marks each tool; `core_text_read` is listed there as new and unit-tested, not part of the 2026-10-16 functional audit).
- **Clean room is not an OS sandbox**: it is a rule about which tools Craft Anything offers and refuses. A coding agent you run still acts as you, with its own permissions (`README.md` "Clean room or Deep").
- **Clean room offers only 108 tools** (measured over MCP); expecting the other 195 is a mode error, not a missing install.
- **Installing dependencies runs code**: npm install scripts, Rust build scripts and Python source packages execute on your machine. Craft Anything asks before a command kind it has not seen in the project; "always allow" then covers every later command of that kind, so grant it only for trusted dependencies (`README.md` "Responsible use").
- **`core_text_read` is not a parser**: it refuses a file with a zero byte in its first 8 KiB, cuts lines over 256 KiB, caps at 64 MiB, and runs nothing; use `core_target_triage` or the native tools for binaries (`crates/engine/src/tools/text_tools.rs`).
- The managed tier is still "next"; the browser build is a viewer, not the full workbench (`apps/craft-anything-web`; `README.md` Status).
- It **never bypasses DRM, logins or anti-cheat**, and the builder is told not to copy logos/photos/text without confirmation of ownership — respect that when writing requests (`README.md` "Responsible use").

## How to operate

- GUI: `open -a "Craft Anything"`; the app binary is `Contents/MacOS/craft-anything`. **The macOS bundle ships `craft-anything-cli` beside it** (`Contents/MacOS/craft-anything-cli`, 0.6.1) — no separate install is needed on a launcher install; on another machine get it from the release assets or `cargo install --path apps/craft-anything-cli --locked`, and keep versions matched. Do not launch the GUI just to run a CLI command.
- Mode: switch Clean room/Deep in the title bar or Settings, `craft-anything-cli settings-set --key deep_mode --value true`, or `--deep`/`--clean-room` per CLI run.
- Typical agent flow:
  ```sh
  craft-anything-cli doctor                      # what's missing (agents, engines, AI)
  craft-anything-cli capabilities                # toolsets, availability, engines
  craft-anything-cli triage ./target.bin         # first look, evidence records
  craft-anything-cli rebuild https://example.com "Recreate this website" --rounds 2
  craft-anything-cli rebuild - "A snake game in Rust"
  craft-anything-cli rebuild https://example.com "Make the header blue" --continue-in "<folder>"
  craft-anything-cli report --out report.md      # readable report from the ledger
  ```
- Approvals for one project (the tool's `--project` is the project folder, not the CLI's global evidence project):
  ```sh
  craft-anything-cli project-approvals-set --project "<project folder>"
  craft-anything-cli project-approvals-set --project "<project folder>" --kind publish --mode refuse
  ```
- Read a source text without a build: `craft-anything-cli core-text-read --path "<absolute path to notes.md>" --offset 0 --limit 200`.
- Serve the tools: `craft-anything-cli mcp --all-tools` (all 323 in Deep) or `craft-anything-cli mcp --restricted --inbox "<folder>"` on a shared host. A Clean room server can list only the 108 Clean-room tools, whatever `--all-tools` says. The global `--allow-run` skips the consent prompt for tools that run code or change a device — use it only on a target you own.
- Settings live in `config.toml` (`engine::settings::config_dir()`, version 3); `craft-anything-cli doctor` output is the live answer for paths and installed engines.

## Working with an AI agent

- **You are also the builder Craft Anything drives.** When its coding-agent bridge launches you, read the inbox/notes flow: the person's answers arrive via the `builder-notes` hook; approval-required actions go through `core_action_approve` rather than being assumed. Your CLI calls inherit `CRAFT_ANYTHING_AGENT`, so they are treated as an agent's: they cannot loosen a project's approvals (`crates/engine/src/tool.rs` `AGENT_ENV`; `apps/craft-anything-cli/src/main.rs` `caller`).
- **Study first, honestly**: keep the investigation memory current (`core_investigation_show`, `core_brief_write`, `core_plan_update`, `core_hypothesis_record`, `core_finding_record`, `core_handoff_write`) — the MCP prompts enforce this discipline and it makes your answers auditable. The embedded skill `setup` installs says the same (`crates/setup/src/skill.md`, version 2).
- **Respect the mode.** In Clean room the look-inside tools are absent from the list and refused with `details.reason` `clean_room`; don't try to work around them. A capture or transcript made in one mode is not resumed in the other; switching to Deep is the person's decision.
- **Prepare inputs** in formats the toolsets open (archives, binaries, captures, DB dumps); use `core_archive_extract` rather than shelling out, so evidence lands in the ledger. For plain source text, `core_text_read` keeps pages, offsets and counting in the evidence record.
- **Verify rebuilds** from `checks/` outputs and the per-round comparison reports; a "Ready" step is a claim — open the result and re-check before telling the person it matches. A kept check round (`progress.checked`) means nothing it looked at changed, not that you looked again.
- **Don't run `setup --yes` (or `setup --client …`) over an entry that already lists every tool**: `setup` writes the plain `mcp` command and silently drops an existing `--all-tools`, leaving the core toolset. Read the client's config first; `setup --dry-run` is safe and changes nothing (`crates/setup/src/plan.rs` `default_command`; `crates/setup/src/skill.md`).
- **What not to attempt:** bypassing DRM/logins/anti-tamper (refused by design), promising Codex/Copilot/Grok builds, editing `craft.json`/`.cany` by hand while a run is active, quoting the README's 320-tool number, assuming Ghidra is present (check `doctor`), serving MCP to a shared host without `--restricted`, or loosening approvals from an agent.

## Verification protocol

1. **Round-trip on a throwaway target first**: rebuild a tiny known website with `--rounds 1`, then read `craft.json`, `checks/round-1/` and `app/` before real work.
2. **Cite evidence ids** for every claim about the original; absence is not proof.
3. **Version your project folders** (copy the whole folder; every file carries a version and a newer file refuses saves).
4. **One project per run**: never edit a project folder while a rebuild is active; `--resume` exists for continuation.
