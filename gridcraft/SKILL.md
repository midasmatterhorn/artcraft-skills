## Overview

GridCraft is an open-source, clean-room reimplementation of Microsoft Excel's workflow in pure Rust (`README.md`), by the ArtCraft team; source: `github.com/storytold/gridcraft`. XLSX is the native document format, and the architecture is engine-first: every ribbon button, menu item, dialog OK, keystroke and mouse gesture is a *command* (`crates/engine/src/cmd/`), reachable over a JSON control channel, an MCP server, a headless CLI and (in the web build) a page-level JavaScript API. Maturity is **alpha**: the core workflow (open XLSX → edit/format → sort/filter → chart/pivot → print to PDF → save XLSX) works end to end, but the project's own estimate is ~75% feature breadth and ~50% "ready for real work" (`docs/target-app-parity.md` summary; `ROADMAP.md`). It runs natively on macOS 11+, Windows, Linux and BSD, and in the browser via WebAssembly (`apps/gridcraft-web`). The UI runs on egui 0.37, patched to the storytold fork (`Cargo.toml` `[patch.crates-io]`).

## Capabilities (verified)

### Core workbook and editing
- **One native window per workbook window:** `view.newWindow` opens another window **on the same workbook** (no clone; saving from either window saves it), `view.arrangeAll` tiles the windows, `window.list`/`window.close` manage them, and `view.switchWindows`/`window.activate {index}` switch workbooks (`crates/engine/src/cmd.rs`).
- Three built-in samples `budget`, `sales`, `grades`: `file.new {sample}`, CLI `--sample`, URL `?sample=` (`crates/engine/src/sample.rs`).
- **385 engine commands** (unchanged at v0.19.1; **+0/−0** this release); **281 of the 296 Excel catalog ids implemented, 94.9%** (unchanged) — `crates/engine/src/cmd/*.rs`, `crates/engine/src/catalog.rs`, generated `docs/parity-checklist.md` (the 15 unimplemented entries are listed there).
- Formatting: fonts, fills, borders, alignment, merges, Excel's number-format language (`crates/numfmt`), cell styles and themes, conditional formatting (CellIs, expression, text, top-10, above-average, time period, duplicate/unique, colour scale, data bar, icon set) and data validation (whole, decimal, list, date, time, text length, custom).
- **Cell reading direction (new at v0.19.1):** Format Cells ▸ Alignment offers Context / Left to right / Right to left, i.e. `home.formatCells {range, style:{align:{reading_order:"Context"|"LeftToRight"|"RightToLeft"|null}}}` (`crates/engine/src/cmd/format.rs:88`), modelled as `ReadingOrder` (`crates/model/src/style.rs:354`), written and read as the `readingOrder` attribute incl. differential styles (`crates/xlsx/src/styles.rs:272,616-618`). It is per cell and independent of sheet RTL; **Context** follows the first non-whitespace character's bidi class (`crates/ui-egui/src/text_direction.rs`), and the formula bar and conditional-format styles follow it (`crates/ui-egui/src/formula_bar.rs`, `crates/ui-egui/tests/arabic_bidi.rs`).
- Tables (structured references, header/total rows, banded rows, style gallery, Resize Table, remove duplicates), notes and threaded comments with replies/resolution/timestamps, hyperlinks, pictures floating or inside a cell (PNG/JPEG only), shapes and text boxes (10 `ShapeKind`s: rectangle, rounded rectangle, ellipse, triangle, line, arrow, text box, icon, ink, equation), checkboxes, freehand ink with Ink to Shape, sparklines (line/column/win-loss).
- **Form controls:** buttons, sliders and spin buttons placed on the sheet, with `control.list`, `control.format` (name, text, linked cell, min/max/step/page/value, horizontal, print, locked), `control.assign` (a macro or a command with params), `control.setValue` and `control.press`. A button never opens a web page or a dialog, and `control.press` on a workbook that came from a file asks first (`crates/engine/src/cmd/controls.rs`; UI `crates/ui-egui/src/form_controls.rs`; XLSX `crates/xlsx/src/controls.rs`).
- **One object selection** across charts, pictures, shapes, equations and slicers, with eight resize handles; only the selected object's handles resize, a press elsewhere on it moves it, and each drag is its own undo step (`crates/ui-egui/src/objects.rs`). `ui.object.select {id?, kind?}` selects one and replies `{selected, rect}` in window points.
- Editing: fill handle (drag; right-drag for Copy Cells / Fill Series / Fill Formatting Only / Fill Without Formatting / Series…), AutoFill with the Auto Fill Options button, Flash Fill, Paste Special, Format Painter, Find/Replace (now with `within: "selection"` and a bit-parallel wildcard matcher), Go To, Go To Special, Watch Window, undo/redo with bounded history. A repeated row or single cell pasted into a filtered selection skips the hidden rows; a taller block is pasted straight down (`crates/engine/src/cmd/edit/paste_special.rs`).
- **Paste a picture from the system clipboard** at the active cell (`crates/ui-egui/src/app/clipboard.rs` runs `insert.picture`).
- AutoSum (`formulas.autoSum`, ⌘⇧T): a single cell guesses the numbers above it, else the numbers to its left (the guessed range now stops at a blank cell, #3291); a multi-cell selection gets column totals below and row totals in the empty last column (one undo step). Options ▸ Formulas Maximum Iterations / Maximum Change; Options ▸ General "Highlight the active cell's row"; show/hide sheet tabs and scroll bars per workbook (`view.showSheetTabs`, `view.showHorizontalScrollBar`, `view.showVerticalScrollBar`).
- Background error checking (green corner, warning button, Convert to Number, Circular References); AutoSave switch that saves only workbooks that already have a file; "Remove personal information on save" kept and honoured; R1C1 reference style kept; page margins written as their decimals.
- **Opening recalculates every formula** (`DocState::new` → `Calc::recalc_all`, `crates/engine/src/lib.rs:314`), so a workbook with volatile formulas runs them on open; there is no recalc-on-open switch (`from_saved`, the constructor that keeps a file's values unevaluated, is used only by a test). To read what a file *stores*, bypass the session and inspect the package (`gridcraft-cli check` does exactly that).
- Slicers exist as in-sheet filter widgets over one table column, but are **not** written to XLSX.

### Formulas and calculation
- **513 of Excel's 523 worksheet functions by name, 504 working (96.4%) — unchanged at v0.19.1** — including dynamic arrays and spilling, LET/LAMBDA (a self-calling LAMBDA stops at 140 calls with `#NUM!`), MAP/REDUCE/SCAN/BYROW/BYCOL/MAKEARRAY, GROUPBY/PIVOTBY (a GROUPBY total depth of 2 or more adds subtotals), structured table references and iterative calculation for circular references — `docs/function-parity.md`, `crates/functions/src/`, `crates/calc/src/eval.rs`.
- **Legacy array formulas (new at v0.19.1):** a formula saved without dynamic-array metadata (no `cm` attribute, which includes every `.xls` formula) is read with Excel's implicit intersection (`@`) and does not spill; a typed `=@F(…)` saves and reopens with the same single value, and only a genuinely dynamic formula gets `cm` metadata on save (`crates/xlsx/src/array_formula.rs`, `crates/engine/tests/legacy_array_functions.rs`, #410).
- **Lookups onto a blank target** follow Excel: VLOOKUP/HLOOKUP/LOOKUP/XLOOKUP keep the empty target as a blank (the cell displays 0 only as the formula's final result), so `ISBLANK` and `&` see it as blank (`crates/functions/src/lookup.rs`, #374).
- Evaluate without editing: `gridcraft-cli eval '=SUM(A1:A9)' --in book.xlsx` or `formulas.evaluate`. A formula that could not be typed into a cell is an error that says why, not a silent `#VALUE!`.
- Calculation settings travel with the workbook: automatic / automaticExceptTables / manual, iterative on/off, max iterations and max change (`formulas.calculationOptions`). Set precision as displayed rounds calculation results.
- **Python cells** (a cell type, not an Excel function): `python.set {cell, code, output?}` and `python.output` set the code and its return type (`value`/`object`); Python mode edits the code in the formula bar (`ui.pythonMode`, Ctrl+Alt+Shift+M toggles the return type). Code and a file's cached result are stored; **GridCraft never runs Python**, so new or changed code shows `#BLOCKED!` (`crates/engine/src/cmd/python.rs`, `crates/xlsx/src/python_part.rs`).
- **Equations:** Insert ▸ Symbols ▸ Equation (`insert.equation {latex}`, `equation.edit`), LaTeX source laid out by `gridcraft-math` and drawn from the cached layout, written as OMML and read back from OMML for a common subset (`crates/xlsx/src/omml.rs`). The source is capped: 4 KB, nesting 32, at most 2,500 matrix cells, no macro definitions (`crates/math/src/lib.rs`).
- Carried hardening: accounting negatives read as negative numbers; `INDEX(A1:C3,2)` on a 2-D reference is `#REF!`; REGEXREPLACE bounds each replacement; a 16-million-cell budget is charged before scanning; arrays the text functions build are capped, and TEXTJOIN and CONCAT build into a capped output instead of first copying every input (`crates/functions/src/text.rs`).

### Files it reads and writes
- **`.xlsx` is native read/write**: cells, shared/array/dynamic/legacy formulas, styles incl. per-cell reading direction, themes (per-script typefaces; `<scheme val="minor"/>` kept), merges, conditional formats, validation, tables, notes and threaded comments, hyperlinks, names, freeze panes, outlines, print settings, pictures (shared media written once), shapes incl. ink, sparklines, form controls, PivotTables, sheet/workbook protection and Allow Edit Ranges, calc settings — each sheet keeps its sheetId across a rewrite, and a formula an edit does not change keeps its stored text exactly as saved (`crates/formula/src/adjust.rs`, `crates/formula/tests/it/adjust_oracle.rs`).
- **Pass-through on save** (kept when their owner survives): custom document properties, ribbon customisation, custom XML, external workbook links (never followed or refreshed), data connections, sheet query tables, printer settings, ActiveX and unmodelled form controls (the three modelled kinds are rebuilt; unknown controls pass through), OLE objects, sheet backgrounds with their VML, header/footer pictures, chart sheets.
- `.xlsm` / `.xltm` keep their VBA project byte-for-byte; macros are **never executed**. `.xltx`/`.xltm` save with the template content type.
- **Import-only**: `.xls`/`.xlt` (BIFF8: values, formulas — now with the legacy implicit-`@` reading — number formats, merges, sizes, names, calc and sheet-display settings; duplicate sheet names are refused, chart/macro/dialog sheets skipped), `.xlsb` and `.ods` (worksheet values and cached formula results only), and `.slk` SYLK (values, R1C1 formulas converted to A1, number formats, column widths; save refused).
- **Text/data**: CSV and TSV/TXT/TAB with delimiter/encoding detection; writes the *displayed* text, keeps the separator a file was opened with, refuses output over 512 MiB; `file.open {csvAsText:true}` keeps every field as text. `.json`/`.scjson` is a debug serde dump. **HTML: `file.exportHtml` writes one sheet as a table (pictures as data-URI images, charts as inline SVG, at most 100,001 rows), and opening a page imports its table as a sheet** (header cells bold; `x:num` values only when values are read; no full HTML document model). The charts on one exported page share a 64 MiB SVG budget and the export fails past it rather than dropping a chart (`crates/engine/src/chart_svg.rs`).
- **`.pdf` export**: own PDF 1.7 writer; `file.exportPdf {path?, sheets?: active|all, range?, fitToPage?}` returns `{pages, bytes, path}` or base64; `file.print` returns the same PDF. `http(s)` hyperlinks and internal cell destinations become real PDF link annotations; `file:` links are omitted.
- **Password-encrypted `.xlsx` open** (Agile AES and Standard encryption, [MS-OFFCRYPTO]) via a `password` param; the Agile `dataIntegrity` HMAC is verified. RC4/Extensible and encrypted `.xls` are refused.
- **Save is refused** for `.xls`, `.xlsb`, `.ods` and `.slk` with an explanatory message. Content wins over the extension.
- Hard caps: 512 MB per decompressed XLSX part and 1 GB per package, 2 GB per file read, 100,001 HTML rows, 512 MiB CSV/TSV output, 64 MiB SVG for one exported page's charts, 16,000,000 cells per array result. Opening an XLSX warns for each skipped drawing object and chart.

### Charts, PivotTables and analysis
- **26 `ChartKind`s (unchanged at v0.19.1)**: column/bar/line/pie/doughnut/area/scatter/bubble/radar/histogram/waterfall/funnel/treemap/sunburst/box-whisker/stock/combo and subtypes; chartex parts for histogram/box-whisker/waterfall/funnel/treemap/sunburst, six trendline types, Recommended Charts, Select Data, Switch Row/Column, Change Type/Colours/Layout. **A doughnut draws every series as its own concentric ring.**
- **Chart work is capped and clipped before evaluation:** 100,000 points per series (255 series), 2,000,000 points per chart — when a chart would exceed it every series keeps its first `2,000,000 / series` points and no series is dropped — and at most 16 trendlines per chart (`crates/chart/src/resolve.rs`, `crates/chart/src/tests/budget.rs`). Label fitting and legend measuring avoid hundreds of text layouts per render (`crates/chart/src/render/legend.rs`, `crates/ui-egui/src/chartview.rs`).
- Chart objects move and resize, use the shared object selection, and all 2-D kinds survive the XLSX round trip. **PivotCharts that arrive in a file are read and kept**, their series rebuilt from the report when it refreshes; there is no Insert ▸ PivotChart command.
- PivotTables: field list, Filters/Rows/Columns/Values areas, report filters, filter items by picking labels, layouts, date grouping, show-values-as, calculated fields, values on rows, grand totals, styles, refresh, change source; round-trip to/from XLSX. Show Details and Enable show details exist (command only).
- Data tools: sort (multi-key), AutoFilter, Advanced Filter, remove duplicates, text-to-columns, Flash Fill, group/ungroup/subtotals, consolidate, scenario manager, Goal Seek, data table; Outline Settings and Show Outline Symbols.
- Solver (Simplex LP with integer/binary branch-and-bound, GRG Nonlinear, Evolutionary; **Answer, Sensitivity and Limits** reports; save/load model), Forecast Sheet with hindcast, **Analysis ToolPak with all 19 tools** (`crates/engine/src/cmd/analysis.rs`).
- Printing: native macOS/Windows/Linux printing through the pinned shared `craft-print` library, Page Setup, Page Break Preview, Page Layout view with rulers, draggable margins and in-place header/footer editing.
- Conditional formatting's New Formatting Rule formula box takes references clicked or dragged on the grid.

### Text, languages and scripts
- **Arabic and other right-to-left text:** the egui 0.37 renderer shapes with harfrust (its shared shaper, `Cargo.lock`) and lays text out with Unicode bidi (`unicode-bidi = "=0.3.18"` in `crates/ui-egui/Cargo.toml`); cells, the in-cell editor and the formula bar follow the cell's reading direction, caret movement and word deletion are visual (`crates/ui-egui/tests/{arabic_bidi,arabic_editing}.rs`). Arabic faces are part of the fallback chains — fontconfig's pick, then system faces (Geeza Pro on macOS, Tahoma/Arial/Segoe UI on Windows, Noto Sans/Naskh Arabic on Linux) and craft-fonts' Noto Sans Arabic (`crates/ui-egui/src/theme/font_fallback.rs`, `crates/ui-egui/src/craft_fonts_policy.rs`).
- **CJK and script fallbacks** share the Latin baseline in cells, editors and window titles; other scripts, symbols and emoji keep their alignment (`crates/ui-egui/src/grid/quadrant.rs`, `crates/ui-egui/tests/cjk_baseline.rs`, `docs/ui-parity.md`).
- **Arabic-aware measurement:** AutoFit width, wrapped-row height and PivotTable column fit estimate Arabic letters at 0.48 em, Arabic-Indic digits at ASCII width, and give vowel/direction marks no width (`crates/engine/src/cmd/format/sizes.rs`).
- **Number formats:** Excel's `B1` (Gregorian) and `B2` (Hijri) calendar prefixes are hidden and `B2` renders the tabular Hijri calendar with Arabic month/weekday names; a misplaced prefix makes the code General and `TEXT` return `#VALUE!` (`crates/numfmt/src/calendar.rs`, `crates/numfmt/src/parse.rs`, tests in `crates/numfmt/src/tests.rs`). Values round on Excel's 15-significant-digit decimal string, half away from zero, so `0.00` shows 2.675 as 2.68 (`crates/numfmt/src/decimal.rs`, `crates/numfmt/tests/golden/`).
- **Interface languages**: 19 (`Language::ALL`): en, es, el, zh, ja, ko, ru, pt-BR, de, cs, fr, sr, pl, it, uk, vi, nl, ro, tr. Untranslated strings fall back to English; command ids, document text, formulas and number formats stay English/en-US. `app.language.set {language|code}` switches at runtime.

### Automation surface (the reason to read this skill)
Counts at v0.19.1, with v0.17.0 in brackets where it differs: **385 engine commands** (unchanged); **281/296 catalog ids** (unchanged); **22 MCP tools** (unchanged); **12 CLI subcommands** (11); **35 control method names in 30 dispatch arms** (unchanged) plus command-id passthrough; **18 UI-only command ids** (unchanged); **72 shortcut bindings on command specs** (unchanged) plus 5 macOS-only overrides; **413 key-tip sequences** (unchanged); **19 interface languages** (unchanged); **26 chart kinds** (unchanged); **513/523 worksheet functions** (unchanged); **3 MCP resources** (unchanged); **14 `check` round-trip categories** (unchanged).

- **The control channel requires a token:** the first line of a connection must authenticate with the app's token, and a connection that does not — or later sends a malformed line — is answered once and closed (`apps/gridcraft/src/control_server.rs:4-5,23-29,59-73`; `gridcraft_mcp::control_auth`). The token is `--control-token <token>` or `GRIDCRAFT_CONTROL_TOKEN` (at least 16 characters), else 256 random bits written to a file only the user can read whose path is printed to stderr (`$XDG_RUNTIME_DIR/gridcraft/control-<port>.token`, else `~/.cache/gridcraft/…`; Windows `%USERPROFILE%\.gridcraft\…`). `gridcraft-cli send` and `mcp --connect` read it automatically.
- **CLI `gridcraft-cli`** (headless; the app bundle ships no CLI): `info`, `convert`, `eval`, `cat`, `run`, `check`, `sandbox-check`, `commands`, `functions`, `mcp`, `send`, `version` — **12 subcommands** (`apps/gridcraft-cli/src/main.rs:85-96`). Version 0.19.1.
- **`sandbox-check` (new):** with no program it runs a confined copy of itself that tries each action the sandbox must deny (reading outside the policy, writing, TCP, starting a process) plus two that must still work (a thread, reading an allowed file) and prints one line per attempt; with `-- PROGRAM ARGS…` it runs that program confined (`--read PATH`/`--exec PATH` add policy paths). Exit 0 = everything as required, 1 = not (a refused launch included), 2 = GridCraft has no sandbox for this system (`apps/gridcraft-cli/src/sandbox_check.rs`, `docs/sandbox.md`). macOS needs `/usr/bin/sandbox-exec` (deprecated by Apple); Linux needs Landlock ABI 3 (kernel 6.2). Windows, BSD and the web have none.
- `check` is the one to remember: it recalculates every formula against the file's Excel-cached values (skipping volatile formulas and files flagged `fullCalcOnLoad`), then writes and re-reads the workbook through GridCraft's own XLSX writer and compares **14 categories** — package, sheets, values, formulas, numFmts, merges, names, tables, condFormats, validations, charts, comments, hyperlinks, pivots — and validates the package. Flags `--tolerance 1e-9` and `--max-report N`; exit 1 on any difference; `--json` emits schema `gridcraft-check/1`.
- **MCP server** over stdio, protocol `2025-06-18` (older clients are answered in their own version); headless (`--in FILE | --sample NAME`) or remote (`--connect PORT`). **22 tools**: `execute_command`, `list_commands`, `inspect_workbook`, `read_range`, `write_range`, `set_cell`, `get_cell`, `evaluate_formula`, `select`, `format_range`, `insert_chart`, `create_table`, `sort_range`, `filter`, `open_workbook`, `save_workbook`, `new_workbook`, `undo`, `redo`, `screenshot`, `list_functions`, `list_windows`. A message over **16 MB** is answered with `-32600` ("message too large (16 MB max)") and dropped, without allocating it (`crates/mcp/src/server.rs`). Resources: `gridcraft://workbook`, `gridcraft://commands`, `gridcraft://functions`; `prompts/list` is empty.
- **Control-channel methods** (35 names in 30 match arms; aliases share an arm): read state — `engine.execute` (aliases `command`, `ui.menu.invoke`), `engine.commands`, `engine.journal` (10,000 entries / 64 MB, passwords stripped), `document.inspect`, `sheet.read`, `cell.get`, `selection.stats`, `ui.inspect`; objects and UI — `ui.object.select`, `ui.ribbon`, `ui.set`, `ui.dialog`, `ui.dialog.set|confirm|cancel`, `ui.message.dismiss`, `ui.edit.begin|text|commit|cancel`, `ui.key`, `ui.text`, `ui.move`, `ui.click`, `ui.drag`, `ui.cell.click`, `ui.cell.drag`, `ui.resize`, `ui.focus`, `ui.screenshot`; files and lifetime — `app.open`, `app.save`, `app.quit`. Any other method that names an engine command id runs that command (`crates/ui-egui/src/control.rs`).
- **UI-only commands** reachable through `engine.execute` in the running app (so also over `mcp --connect`, not in a headless `gridcraft-cli mcp` session); `engine.commands` marks them `"ui": true` and serves **18**: `ui.ribbonTab`, `app.checkForUpdates`, `view.collapseRibbon`, `view.expandFormulaBar`, `ui.pythonMode`, `view.darkMode`, `view.theme`, `view.animations`, `options.autoComplete`, `options.highlightActiveRow`, `view.interfaceScale`, `ui.dialog`, `ui.backstage`, `ui.printSettings`, `ui.printSubmit`, `app.language.set`, `app.language.english`, `app.language.japanese` (`crates/ui-egui/src/control.rs` serves the list; `crates/ui-egui/src/app/commands.rs` runs them).
- **Recorded scripts** (Automate tab): `automate.recordActions`, `automate.newScript`, `automate.allScripts`, `automate.runScript`, `automate.trustScripts`, `automate.deleteScript`, `automate.stopAction`. A workbook opened from a file that carries scripts starts untrusted; steps may not call `file.*`, `link.*` or `window.*` or pass a `path`. Scripts are stored in the workbook as the hidden defined name `_sc_scripts`, so they round-trip XLSX.
- **Engine building blocks**: undo groups, the recording buffer, document `Trust`, and the chunked hidden-name stash `_gc_<key>_<n>`.
- **Web build**: same UI crate via the eframe web runner; URL flags `?sample=`, `?webgl`, `?chrome=none|notitlebar|nofiletab`, `?host=parent&author=`; **`data-host="page"` on the canvas lets a page host GridCraft in its own document** (`apps/gridcraft-web/src/host.rs`, shared crate `craft-web-host`); preferences in `localStorage`; no TCP control channel. **`window.gridcraft` (new) is on the page in every mode**: `request(method, params)` calls any control method, and `execute`, `commands`, `docInspect`, `uiInspect`, `screenshot` are shortcuts; each returns a Promise that rejects after 30 s, and a call the app had not started is skipped (`apps/gridcraft-web/src/api.rs`, `packaging/web/README.md`).
- **Programmatic calls never open dialogs**: `file.open`/`file.save`/`data.getData`/`data.fromTextCsv` without a file path return "missing `path`…: programmatic calls never open dialogs".

## Known limitations and not-implemented

- **Partial:** `.xls` import covers values, formulas, number formats, merges, sizes, names, print area/titles, calc settings and WINDOW2 sheet-display options; no fonts, fills, borders, charts, pictures, comments, conditional formats, validation, hyperlinks or freeze panes; chart/macro/dialog sheets are skipped, BIFF5 and FILEPASS files refused. `.xlsb`/`.ods` import values and cached formula results only. `.slk` import is values, R1C1 formulas, formats and widths only. None of the four is ever written.
- **The sandbox is groundwork, not a Python runtime.** `crates/sandbox` confines a spawned helper process and only `gridcraft-cli sandbox-check` starts it today; Python cells still show `#BLOCKED!` for new or changed code and never execute (`docs/sandbox.md`, `crates/engine/src/cmd/python.rs`). A framework-build Python that re-execs its real interpreter is refused by the macOS profile, and Python's `asyncio` has no socket pair on Linux.
- **Regional formats are not wired.** `crates/core/src/region.rs` holds CLDR-derived conventions and `Workbook::region` exists, but no UI page, command or format path reads it: typing `1.234,56` or seeing `25/09/2026` still does not depend on a region — everything is en-US (`crates/model/src/workbook.rs:271-276`).
- **Encryption is read-only**: Agile and Standard `.xlsx` open with a password; saves are always unencrypted and have no save path, so Save asks where to go. RC4/Extensible and encrypted `.xls` are refused.
- **Macros never run.** VBA is carried byte-for-byte only into `.xlsm`/`.xltm`; any other save drops it. GridCraft's recorded scripts are not VBA.
- **Python cells are storage, not execution.** Code and a file's cached result round-trip; GridCraft does not run Python, so new or changed code shows `#BLOCKED!`, and there is no `PY` worksheet function.
- **Equations are LaTeX-source shapes.** OMML outside the supported subset comes back as a plain text box, and an equation is only as good as `gridcraft-math`'s layout, not a full Office equation editor; macros, very deep nesting and large matrices are refused rather than laid out.
- **Excel-repair-free output is unproven**: no real corpus and no Excel verification. Unmodelled content is dropped when its owner is rewritten — slicers and slicer caches, timelines, the data model, query tables attached to tables, unmodelled `extLst`; chart sheets are passed through unchanged but cannot be viewed, edited or created (open now warns for each skipped drawing/chart).
- **Slicers/timelines:** slicers can be created and clicked in-sheet but are not saved to XLSX; timelines are catalogued but not implemented.
- **Charts are shallow:** no 3-D types, no axis options (min/max/log/units), no error bars, no per-point formatting; data labels and gridlines are just booleans; ~26 of Excel's ~60 subtypes (~43%); chart sheets are not editable. A chart is also bounded at 100,000 points per series and 2,000,000 points per chart, so a very large range is drawn truncated (never silently dropped series). Move, resize (eight handles) and the Format Chart Area dialog do work. PivotCharts open and keep their link to the PivotTable, but there is no command to insert one.
- **PivotTables:** no calculated items, `GETPIVOTDATA`, timelines, PivotCharts command, number grouping or data-model pivots; filter items select labels only (no Top-10, condition or value filters); Show Details and Enable show details exist but have no Options dialog; XLSX round-trip has not been checked in Excel.
- **No Power Query or data model:** Get & Transform is only From Text/CSV, Get Data and From Table/Range; Refresh All refreshes PivotTables only. No From Web (`data.fromWeb` is absent), Stocks, Geography, Relationships or Analyze Data.
- **Scale:** recalculation is single-threaded (this release added a spill index, constant-block memoisation and selection instead of sorting in MEDIAN/PERCENTILE/QUARTILE/LARGE/SMALL, but no threading); the project reports ~100 MB workbooks failing to open (#175). Whole-range work is capped and refuses with an error instead of hanging.
- **Text:** Arabic and other right-to-left text now lay out with bidi in cells, editors and the formula bar (shaping is the renderer's harfrust shaper), but there is still no Arabic interface catalog and no mirrored shell; Devanagari and Thai shaping are unverified, and `docs/localization-parity.md` still carries a stale sentence claiming Arabic does not join or reorder — check Arabic joining and vowel-mark placement visually before promising typographic quality; a right-to-left sheet mirrors the grid, and text follows its cell's reading direction inside its box, but sheet tabs, the horizontal scrollbar and printing/PDF are not mirrored. PDF export sets characters outside WinAnsi in a predefined, **non-embedded** Adobe-GB1 CID font (STSong-Light / UniGB-UTF16-H): Chinese is tested; Japanese/Korean coverage depends on that font; **Arabic/Devanagari/Thai have no glyphs there**, and PDF/printing do not apply bidi.
- **Accessibility:** AccessKit is enabled and some widgets set node labels, but grid cells and the ribbon are not exposed as an accessible tree; Check Accessibility is a basic scan; no high-contrast mode; physical screen-reader behaviour in bidi text is unverified (`docs/localization-parity.md`).
- **No VBA/Office Scripts/add-in or custom-function API, no collaboration/co-authoring, no mobile build, no in-app AI.**
- **Functions:** 10 of Excel's 523 names are absent (GETPIVOTDATA, IMAGE, STOCKHISTORY, TRANSLATE, DETECTLANGUAGE, CALL, REGISTER.ID, RTD, COPILOT, PY) and 9 are error stubs (7 CUBE functions, WEBSERVICE, FILTERXML). `docs/function-parity.md`'s headline agrees with the code; its totals row (505/496, "18 missing") is stale — the honest split is 513 present, 10 absent, 9 stubs.
- **HTML is a table extractor, not a document model:** opening a saved page imports a table as a sheet (first/only table, header cells bold), and `file.exportHtml` writes one sheet; there is no HTML editing.
- **Objects:** inserted icons lose their artwork on XLSX save (#551); Office InkML is not imported; pictures must be PNG/JPEG.
- **Form controls are three kinds only:** buttons, sliders and spin buttons. A button's action is a macro or a command, never a web page or a dialog; `control.press` on a workbook that came from a file asks for approval.
- **Save semantics:** only `.xlsx` and `.json` saves clear the dirty flag and become the document's file; `.csv/.tsv/.html/.pdf` are exports that leave the workbook dirty; `.xls/.xlsb/.ods/.slk` saves are refused. `file.close {force:true}` and the control-channel `app.quit` discard unsaved changes without asking.
- **Stale repo prose** (verify against code, not docs): README still says "89% of standard ribbon commands" while the generated checklist says 281/296 = 94.9%; `docs/target-app-parity.md:58` still reports "321 command ids" (the registry has 385); `docs/gaps.md` still says "59 command shortcuts" (command specs carry 72) and its §5 was merged with the new Arabic paragraph leaving both an updated and an obsolete "Missing/Evidence" pair; `docs/function-parity.md`'s totals row disagrees with its own headline. Prefer code and the generated `docs/parity-checklist.md`.

## How to operate

### macOS launch, flags, environment
- `open -a GridCraft`; `open -a GridCraft book.xlsx` — Finder double-clicks and `open` arrive as Apple events, and files dropped on the window open too.
- The bundle's binary is `Contents/MacOS/GridCraft`. It takes only these flags: `[--control PORT [--control-token TOKEN]] [--sample budget|sales|grades] [files…]`, plus `--version`/`-V`, which prints `GridCraft 0.19.1` and exits. There is **no `--help`**: any unrecognised flag is treated as a file path and starts the GUI, so do not pass one. **Never pass the internal `--sandbox-launch`, `--sandbox-confined`, `--sandbox-probe-child` or `--sandbox-report` flags** — they belong to the sandbox launcher (`crates/sandbox/src/lib.rs`).
- Environment: `GRIDCRAFT_CONTROL_PORT=<port>`, **`GRIDCRAFT_CONTROL_TOKEN=<token>`** (the control channel requires it), `GRIDCRAFT_NO_PREFS=1` (the mode for agent test runs: no preferences read or written, no log file), `GRIDCRAFT_NO_NATIVE_MENU`, `RUST_LOG` (env_logger-style directives; default `warn,gridcraft*=info`).
- Settings and logs live under `Library/Application Support/GridCraft/` in the user's home: `ui.json`, `prefs.json`, and `logs/gridcraft.log`, rotated to `.1`/`.2` at each start, 16 MiB cap.

### The CLI (installed separately)
The bundle ships no CLI. Install with `cargo install --path apps/gridcraft-cli` from a source checkout, or the release zip `gridcraft-cli-<ver>-macos-universal.zip`.

```sh
gridcraft-cli info book.xlsx [--json]
gridcraft-cli convert in.xls out.xlsx [--sheet Sales]     # input may be .xls/.xlsb/.ods/.slk/CSV/TSV/HTML;
                                                          # output .xlsx/.csv/.tsv/.json/.html/.pdf by extension
gridcraft-cli eval '=XLOOKUP("b",{"a","b"},{1,2})'        # → 2
gridcraft-cli cat book.xlsx --range A1:F20 [--formulas|--csv]
gridcraft-cli run --in book.xlsx --cmd 'cell.set={"cell":"D2","input":"=B2*C2"}' \
    --cmd 'edit.fillDown={"range":"D2:D20"}' --out book.xlsx --print A1:D5
gridcraft-cli check corpus/ --json --tolerance 1e-9       # calc oracle + XLSX round-trip fidelity
gridcraft-cli sandbox-check                               # does this machine confine a helper process?
gridcraft-cli commands --search chart                     # every command and its params doc
gridcraft-cli functions --category statistical            # function list with signatures
gridcraft-cli send 7979 engine.execute '{"command":"home.bold","params":{"range":"A1:C1"}}'
```

- `run` flags: `--in FILE | --sample NAME`, repeated `--cmd`, `--script FILE`, `--out FILE`, repeated `--print RANGE|used`, `--sheet`, `--quiet`, `--csv`, `--formulas`. A `--cmd` is `id`, `id={json}` or `id {json}`; a script has one step per line; blank lines and `#`/`//` comments are skipped. The first failing step stops the run with a non-zero exit.
- `convert` refuses an unknown output extension; `.pdf` goes through `file.exportPdf` and reports bytes/pages; converting a `.slk` works because the input side reads SYLK.
- `check` never writes next to its inputs. `--json` output is schema `gridcraft-check/1`.
- `sandbox-check` prints `sandbox: available (…)`/`sandbox: unsupported (…)` first, then one line per attempt; it writes nothing.

### MCP
```sh
claude mcp add gridcraft -- gridcraft-cli mcp                     # headless in-process session
claude mcp add gridcraft-app -- gridcraft-cli mcp --connect 7979 # drive the visible app
```
Results are one text block holding pretty JSON; failures set `isError: true`. Unknown tools, missing/wrong arguments are JSON-RPC `-32602`; malformed JSON `-32700`; unknown methods `-32601`; a message over 16 MB is `-32600` and dropped. The remote backend uses a 30 s socket timeout: after a timeout, re-read the state instead of retrying blind. `list_windows` enumerates the open workbook windows; address a window where the backend accepts it.

### Control channel (drive the running app)
```sh
GridCraft --sample sales --control 7979
# stderr prints the token file path (or use --control-token / GRIDCRAFT_CONTROL_TOKEN), then
# newline-delimited JSON to 127.0.0.1:7979 — the FIRST line must authenticate with the token:
{"id":0,"method":"auth","params":{"token":"<token>"}}
{"id":1,"method":"engine.execute","params":{"command":"cell.set","params":{"cell":"B2","input":"=SUM(A1:A9)"}}}
{"id":2,"method":"engine.execute","params":{"command":"home.formatCells","params":{"range":"C2","style":{"align":{"reading_order":"RightToLeft"}}}}}
{"id":3,"method":"ui.screenshot","params":{"path":"shot.png"}}
```
- **Authentication is required**: a connection that does not authenticate first is closed, as is one that later sends a malformed line. The first line must arrive within 10 s and be at most 4 KiB; at most 16 connections may be waiting to authenticate. `gridcraft-cli send` reads the token file automatically.
- Run `ui.inspect` first (ribbon tab, editor, open dialog, Backstage page, message, grid rect, scroll, perf, windows) and act on what it shows; `ui.screenshot` needs a presented frame.
- Limits: 64 MiB per request line; 10,000 queued synthetic pointer events and 8 MiB of synthetic input (pointer, key, text and move events share the budget); the server waits 60 s for the UI, then reports a timeout. A request the client abandoned is dropped unrun; if the app had already started it, the reply says the outcome is unknown — read the cell/state before retrying.
- The port binds localhost only and is token-authenticated; do not expose it.
- `ui.dialog.confirm` sends exactly what the dialog's OK sends; dialogs without an OK command return "this dialog has no OK command; drive it with its own commands".

### Document model and save/export flow
- **One native window per workbook window**: `view.newWindow` shares the workbook (no clone; saving from either window saves it), `view.arrangeAll` tiles, `window.list`/`window.close` manage windows, and `view.switchWindows`/`window.activate` switch workbooks. Sheet tabs at the bottom. File opens the Backstage with **9 pages**: home, new (three samples), open (recents), info, saveAs, print, export, options, account.
- Save (`file.save`, `file.saveAs`, ⌘S, ⇧⌘S): the extension picks the format — `.xlsx` (default), `.csv`, `.tsv`, `.json`, `.html`, `.pdf`; a `.pdf` save exports the sheet and leaves the document dirty. `file.saveBytes {format}` returns base64 without writing.
- Exports: `file.exportPdf`, `file.exportCsv`, `file.exportHtml`, `file.printPreview`, and on the desktop `ui.printSettings` / `ui.printSubmit` (native jobs via `craft-print`).
- Opening a `.xls`/`.xlsb`/`.ods` produces a document titled `<name> (imported).xlsx` with no save path; a `.slk` keeps its own name and path, so a later Save is refused (SYLK is import-only) — **Save As `.xlsx` first**. Opening an already-open path switches to it; a password-decrypted workbook also has no save path.

### Keyboard essentials (verified)
- **72 shortcut bindings on command specs** (F3 → Paste Names, Ctrl+8 → Show Outline Symbols, Ctrl+Shift+U formula bar, Ctrl+. → next corner), plus **5 macOS-only overrides**, plus a wider keymap table for number formats, borders, F-keys and Alt/Option combinations (`crates/ui-egui/src/keymap.rs`).
- Essentials: ⌘S save, ⇧⌘S Save As, ⌘O open, ⌘N new, ⌘W close, ⌘Z undo, ⌘Y redo; ⌘B/⌘I/⌘U; ⌘1 Format Cells; ⌘D fill down, ⌘R fill right; ⌃E Flash Fill; ⌘T table; ⌘K link; Ctrl+Shift+L filter; F2 edit; F3 Paste Name; Ctrl+Shift+4 currency; Ctrl+Shift+7 outline border; Ctrl+` show formulas; F9 calculate; Ctrl+[ / Ctrl+] precedents/dependents; Ctrl+6 hide/show objects; Ctrl+8 outline symbols; Ctrl+. moves to the next corner of the selection; Ctrl+Shift+U formula bar.
- Key tips: F10 (or left Alt on Windows/Linux/BSD), then sequence letters; **413 sequences** cover every ribbon tab, including the Excel 2003 menu paths (Alt+I, R; Alt+D, S; …).
- The macOS native menu has Tools ▸ Command Palette… (⌘⇧P).

## Working with an AI agent

**Prefer headless over GUI.** For read/write/convert/verify jobs use `gridcraft-cli` (or MCP) on files: no window, no preferences (set `GRIDCRAFT_NO_PREFS=1` if you launch the app), deterministic. Drive the GUI over the control channel only when the task is genuinely about the UI. Never drive blind — `ui.inspect`/`ui.screenshot` before and after.

Legitimate agent work:
- **Prepare inputs.** Build `.xlsx` from commands (`gridcraft-cli run --script steps.jsonl`), convert `.xls`/`.xlsb`/`.ods`/`.slk`/CSV/TSV/HTML into `.xlsx`, or generate CSV/TSV/JSON and import. Use `file.open {csvAsText:true}` when leading zeros must survive. Remember an import opens as an unsaved "(imported).xlsx".
- **Interpret/repair files.** XLSX is native and documented in code. "Repair" means: open in GridCraft, inspect (`info`, `check`), fix with commands or formulas, save as `.xlsx`. Do not promise recovery of parts GridCraft does not model. Opening recalculates, so read a file's cached values through `gridcraft-cli check`/package inspection rather than by opening it in a session. Legacy formulas that arrive without dynamic-array metadata are read with implicit `@`, so their values match Excel instead of spilling — but a formula whose text you rewrite is saved with dynamic-array metadata if it really is dynamic.
- **Verify exports honestly.** Run `gridcraft-cli check` on round-tripped files, compare `cat`/`info` output against expectations, check PDF page counts and links. A zero exit from `check` means GridCraft agrees with itself and with the file's cached values; it does **not** prove Excel will open the file without a repair prompt.
- **Right-to-left and Arabic work.** Set a cell's direction with `home.formatCells {range, style:{align:{reading_order:"RightToLeft"}}}` (or `Context` to follow the text); do not mirror the whole sheet to make one cell read correctly — `view.rightToLeft` is a sheet-geometry switch and does not change text direction. Arabic in PDF is still unsupported: verify by rendering, and do not promise a PDF with Arabic glyphs.
- **Scripts.** Recorded scripts are a convenience layer over the same command ids. A workbook received from elsewhere carries its scripts as a hidden name; nothing runs until the workbook is trusted, and script steps cannot touch files, links or windows. A leftover undo group blocks undo/redo: clear it with `automate.stopAction`.
- **Sandbox checks.** Run `gridcraft-cli sandbox-check` (read-only, prints a report) before relying on confinement on a new machine; exit 2 means this platform has none. Do not claim Python cells run under it — they do not run at all.
- **Work with two views**: `view.newWindow` shares the workbook — two windows, one document; `list_windows` (MCP) and `window.list` enumerate them; `view.arrangeAll` tiles.
- **Objects and controls**: select an object with `ui.object.select` before clicking or dragging it, and use `control.list`/`control.setValue` rather than clicking a slider or spin button by coordinates. `control.press` on a workbook that came from a file asks for approval — pass `approve` only when the user asked for that action.
- **Embedded web app**: a page can drive GridCraft through `window.gridcraft` (`request`/`execute`/…) instead of a socket; the same command ids and methods apply, with a 30 s promise timeout.

Must NOT attempt:
- Writing `.xls`/`.xlsb`/`.ods`/`.slk`, or saving password protection; expecting macros or Python to run; expecting slicers/timelines to survive a save; assuming a full HTML document import.
- Promising regional typing/display (German `1.234,56`, localized month names, Hijri via a region) — the region table is not wired; only the `B1`/`B2` format prefixes work.
- Raw XML surgery on `.xlsx` files that contain unmodelled parts: GridCraft's own writer is the supported path, and even it drops parts it does not model once it rewrites them. Prefer read-only analysis of such files.
- Treating formulas as locale-independent without checking `docs/formula-input.md`: Spanish input/display exists, but files, commands and APIs use canonical English names and `,` separators.
- Promising PDF output for Arabic, Devanagari or Thai (no glyphs in the CID font, no bidi or shaping); verify CJK output visually first.
- Calling `app.quit` or `file.close {force:true}` while a workbook has unsaved changes: both discard them silently. Save first.
- Connecting to a `--control` port without the token (the connection is closed), or assuming the channel is unauthenticated — it is not.

## Verification protocol

1. **Throwaway round-trip before real work**: new workbook → the exact edit → save `.xlsx` → reopen (or `gridcraft-cli info`/`cat`) → `gridcraft-cli check file.xlsx`. Add the source file itself to `check` when testing formula fidelity, and include a legacy (pre-dynamic-array) formula file if the task involves one.
2. **Never trust a silent export.** CSV/HTML/PDF are one-shot exports with no diff UI. Re-read or re-import the artifact. Remember PDF export cannot be assumed to render Arabic/Devanagari/Thai, and an HTML export fails rather than truncating when its charts pass 64 MiB of SVG.
3. **Version and back up.** Keep the previous copy of any workbook you edit; autosave covers only workbooks that already have a file. For agent runs, save after each logical step (`--out`) rather than at the end.
4. **Update between projects, not during.** The app auto-updates through the ArtCraft Launcher; update, then re-run your round-trip before a new task. This skill was audited at GridCraft **0.19.1**; if the app prints a newer version, re-check the counts in `evidence.md` against the new tag.
5. **After a control/MCP timeout, re-read state** (`cell.get`, `sheet.read`, `document.inspect`) before retrying: a queued request is dropped, but one already taken may still finish.
6. **Trust deliberately.** Do not call `automate.trustScripts` on a workbook you did not create unless the user asked you to run its scripts.
