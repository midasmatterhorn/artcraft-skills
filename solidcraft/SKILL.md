# SolidCraft

**Audit basis.** Refreshed **2026-11-14** against tag **v0.41.0**, commit **`3c8efdb51952ed9a5f3ebc722c2bad1454fe6d80`** ("Release 0.41.0", 2026-11-13; `git rev-parse HEAD` in the pinned checkout confirms it). The installed bundle matches: its binaries print `solidcraft 0.41.0` and `solidcraft-cli 0.41.0`. The previous release this skill described was **v0.40.1** (`0c5292285a7e9331a780c11a2d55f22d8e1c9118`).

**v0.40.1 → v0.41.0 delta.** This release adds a plugin system, not new modelling depth. Two new crates (`craft-plugin`, `craft-plugin-wasm`) run sandboxed WebAssembly components against the same command registry (WIT `craft:plugin@0.1.0`, capability `commands@0.1`; one call is one undo step; no WASI or network). The registry grew 634 → **642** ids (+8: `plugin.inspect/install/list/run`, `model.mesh`, `file.import_cache_clear`, `sketch.spline.handles`, `sketch.spline.reset_handles`); `surface.fillet` is still the only planned id. Typed schemas cover 572 of 642 (was 561 of 634). Design format 54 → **55** (records Move rotation origin, snap-point construction points/axes/planes, dragged spline tangent handles, Split Face loops, projected-vertex names, plugin data). The kernel work in this release is repair: fillets/chamfers on near-tangent corners are mitred again instead of failing (0.30.1 built them, 0.40 did not), STEP **export no longer writes solids inside out**, STEP import keeps sphere/cone-wrapped faces, sheet-metal folds across tabs no longer shatter into strips, and loft/sweep/revolve/boolean cases that 0.40 measured wrong now build. Slow agent commands now compute off the window thread by default on new installs (`agent_off_thread: true`). MCP is unchanged at **22 tools**; the CLI is unchanged at **24 verbs** plus a new global `--plugin-limits` flag.

**Verify against your installed version** — the ArtCraft Launcher auto-updates, so a newer build may differ. Every count quoted here was re-measured at this tag; the method for each is in `evidence.md`.

## Overview

SolidCraft is an open-source parametric 3D CAD application in pure Rust by Tangency Labs (MIT OR Apache-2.0). Sketch, constrain and build solids on an editable feature timeline; change a dimension and the model rebuilds. It is **independent and clean-room**: behaviour is designed from public documentation and general CAD conventions, reference tests use analytic values and FreeCAD as an external oracle, and it is not affiliated with any CAD vendor (`README.md` Disclaimer; `NOTICE`). **Status: early but usable for simple parts** — the generated oracle reports **90/90** reference parts passing, while `README.md` and `docs/capabilities.md` still say "75 of 76" (trust `docs/oracle.md` and `solidcraft-cli oracle`). The B-rep kernel is `solidcore`, a safe-Rust port of NVIDIA's SMLib (`solidcore/README.md`, `crates/smlib/src/lib.rs`); 0.41.0 did not change it. One command registry serves the desktop app (egui), the browser app, the CLI, the control channel, the MCP server and now plugins.

- **MCP server — 22 tools, unchanged from v0.40.1**: `list_commands`, `describe_command`, `execute`, `batch`, `undo`, `redo`, `inspect_design`, `measure`, `body_topology`, `set_parameter`, `check_parameters`, `screenshot`, `compare_picture`, `export`, `new_design`, `open`, `save`, `crash_reports`, `running`, `pending`, `cancel`, `skill_reference` (`crates/mcp/src/tools.rs`; verified live through `tools/list`). stdio JSON-RPC, protocol revisions 2025-06-18 / 2025-03-26 / 2024-11-05 (`crates/mcp-server/src/server.rs`). Headless it runs its own session (`--in part.sc` to start from a file); with `--connect HOST:PORT` it drives the running app so you can watch.
- **Control channel**: loopback-only, token-authenticated, **82 documented methods/commands (protocol methods plus the panel/layout rows) — unchanged from v0.40.1** (same method-table rows in `docs/control-protocol.md`; the file's changes are wording). The token is 256-bit, written to `control/PORT.token`, with the port in `control/current.port`; 16 connections at once, 16 MiB per line, 60 s per request (3600 s for a batch) (`crates/control/src/auth.rs`; `docs/control-protocol.md` "Limits").
- **Real UI input, when a workflow has no command**: `ui.click`, `ui.drag`, `ui.move`, `ui.key`, `ui.text`, `ui.scroll`, `ui.menu`, `ui.pick`, `ui.handles`, `ui.at`, `ui.screenshot`, `ui.render`, `ui.documents`, `ui.operations`, `ui.prefs` (`docs/control-protocol.md` "UI"). `ui.agent_cursor` shows the agent gliding to each pick. `ui.operations` now reports a `next` list (the rest of a running agent batch) and `percent` for byte-counted work, and can cancel a queued design change held behind the running one.
- **CLI — 24 verbs** (`apps/solidcraft-cli/src/main.rs`): 19 listed (`run`, `eval`, `script`, `bench-open`, `bench-agent`, `bench-assistant`, `snapshot`, `render`, `exec`, `commands`, `recipe`, `oracle`, `kernel-cases`, `fuzz`, `mcp`, `crashes`, `licences`, `gpu`, `icon`) and 5 unlisted (`inspect`, `fuzz-one`, `licenses`, `bench-edit`, `save-stress`). - **Scripts** are a JSON list of the same commands: `{"commands": [{"command": "sketch.create", "params": {"plane": "XY"}}, …]}` (`docs/scripts.md`). `script design.sc --out rebuild.json` extracts a design's history as such a script; `eval` returns measurements as JSON.

### Plugins (experimental, new in v0.41.0)

- **Command plugins are sandboxed WebAssembly components** that reach the app only through the command registry. The interface is WIT package `craft:plugin@0.1.0`, capability `commands@0.1`; a manifest declares its entries (1–32), up to 128 command ids it may call, optional slot hints, limits and permissions (`docs/plugins.md`, `docs/plugin-runtime.md`). No WASI or network imports are linked; the server refuses `net`. Fuel, memory, deadline and a resource limiter bound each call; **one successful call is one undo step**, a failed call or trap rolls the whole transaction back, and a refused call poisons it even if the guest catches the error.
- **Install** with `plugin.install` (`{"path": "gears.zip"}`; `dry_run: true` only checks; replacing an installed id needs `replace: true`) or Preferences › Plugins › Install plugin… (desktop). The zip holds one plugin (`plugin.json` + `.wasm`) at its top or in one top-level folder; the host refuses absolute paths, `..`, symlinks, device entries, entries over 16 MiB, more than 64 MiB unpacked, and refuses a newer/unknown capability in plain words. Installing runs no plugin code. On macOS the plugins folder is `~/Library/Application Support/SolidCraft/plugins`; the app also has a Plugins menu that builds a dialog from each entry's input schema (no UI code ships in a plugin).
- **Inspect, then run explicitly.** `plugin.inspect` reads a package **folder** and returns its manifest plus an `approval` SHA-256 over the manifest bytes *and* the component bytes, without instantiating anything. `plugin.run` requires `{"path", "approval": "<exact hash>", "entry", "params"}`; the hash is a content identity, not a signature or author reputation, so re-inspect after any change. `plugin.list` lists inspected and installed packages. A design container reserves `plugins/<plugin-id>/` for plugin data (at most 1024 files, preserved byte for byte whether or not the plugin is installed; the `storage` capability is future work).
- **Agent rules.** Never install or run a plugin unless the user asked for that plugin and reviewed what it requests; show them the inspected permissions/limits/commands first. Over the running desktop, `plugin.run` is refused inside `engine.batch`/`engine.script` (`ui.plugin_standalone`) — send it as its own `engine.execute`; headless CLI scripts may include it. MCP and the control channel keep their file scopes, so allow the package folder explicitly with `--allow-path`. Agent chat in the app asks before executing external plugin code. The plugin runtime is desktop/headless only: no browser execution, no automatic download/update, no custom panels or plugin-defined feature types yet.

### Modelling (what it can actually build)

- **Sketches**: lines, rectangles, circles, arcs, polygons, slots, ellipses, fit/control splines, conics and text on origin planes, offset planes or planar faces; construction geometry, projection, trim/extend, corner fillets/chamfers; spline tangent handles can now be dragged at every fit point (`sketch.spline.handles`, `sketch.spline.reset_handles`) (`docs/capabilities.md`; `sketch.*` commands).
- **Constraints and dimensions**: coincident, point-on-curve, horizontal/vertical, parallel, perpendicular, tangent, curvature (G2), equal, concentric, collinear, midpoint, symmetry, fix; linear, aligned, horizontal, vertical, point-to-line, line-to-circle, point-to-circle, circle-to-circle, radius, diameter, angle, arc sweep, arc length and slot length, parameter-driven. Their own solver places fixed-relative points exactly and uses Levenberg–Marquardt for the rest, reporting remaining degrees of freedom; over-constraining edits are rejected (`docs/capabilities.md`).
- **Features**: extrude, revolve, sweep, loft, fillet/chamfer, shell, draft, holes (presets in `docs/hole-presets.md`), threads (`docs/threads.md`, including the ISO sizes 0.40 lacked: M3.5, M7, M33, M39, M45), patterns, mirror, split, combine, move (`solid.move` accepts `matrix` — rigid 3x4/4x4 — and `origin`), press/pull, offset face, replace face, rib, web, emboss, coil, pipe, boundary fill, bounding solid — on a parametric timeline with rollback and suppression.
- **Split Face along closed loops**: `solid.split_face` now takes `loops: true` with a `sketch` tool, joining its curves end to end first so a closed outline of lines and arcs cuts along itself only. **Split Body** accepts a closed surface (e.g. a sphere), and faces/edges for filleting, chamfering, shelling and edge selection agree on one 2° tangent chain.
- **Snap points**: `construct.point/axis/plane`, sketch tools, joints and the placement point of Box/Sphere/Torus accept the centre, middle or end of an edge, face or sketch curve, and construction follows it when the model changes.
- **Assemblies**: components, occurrences, joints, motion links, motion studies, contact sets, interference and BOM; 0.41 adds a **Constrain dialog** (Mate/Flush/Distance over picked faces, edges, points, planes or axes, with edit/suppress/delete) built on the existing joint commands. **Sheet metal**: flanges, contour flanges (now accepting tangent arcs), hems, fold/unfold, flat pattern, DXF and bend-table export; a fold across several tabs stays single faces instead of exploding into strips, and a sharp zero-radius bend keeps only its outer face. **Plastic enclosure** features, **physical materials** with mass in Properties, **notes**, **point clouds**, and a **Render workspace** with GPU rendering (`render.*`, `docs/render-workspace.md`).
- **Other 0.41 repairs worth knowing**: a loft whose end sections share a sketch is a solid with volume again; a sweep of a thin profile round a sharp corner gives a valid solid; revolving a line skew to the axis gives its exact surface; Through All uses the body's exact size; adjacent tangent profiles merge without a slit; booleans join a filled hollow and tangent faces correctly. Fillet/chamfer failures now say why instead of "status 1001", and a near-tangent sharp corner is mitred instead of failing.
- **Built-in agent skills**: the repo's `skills/` ships 19 Agent-Skills folders. Five are embedded in the binary and served by MCP `skill_reference`: `solidcraft-modeling`, `solidcraft-editing`, `solidcraft-checking`, `solidcraft-mechanisms` and `solidcraft-sheetmetal` (`crates/mcp/src/skill_reference.rs`; live reply lists these five). The `skill_reference` tool description names only four, and `docs/mcp.md` names five but substitutes `solidcraft-reporting` for `solidcraft-sheetmetal` — text drift; the table in code is authoritative. **Read `skill_reference` before a non-trivial model.**

### Files: open and save

- **Native design `.sc`** is a ZIP container: `container.json`, `document.json` (document format **55**) and content-addressed `blobs/<sha256>.<ext>` (`crates/format/src/container.rs`; `docs/design-container.md`). A `.json` path saves the plain JSON design (in a probe, `run --out part.sc` wrote plain JSON — `--out` runs `file.export`; `--save` runs `file.save_as` and writes the container). `.solidcraft` and `.solvecraft` still open and keep their names (`crates/io/src/lib.rs` `DESIGN_EXT`/`DESIGN_EXTS`; `docs/compatibility.md`).
- **Format 55 adds**: rounds recorded by definition, construction points/axes/planes from snap points, a Move's rotation origin, dragged spline tangent handles, Split Face along closed loops, names of projected model vertices in sketches, and plugin data. A design may carry `plugins/<plugin-id>/` files (base64 in a plain JSON design) and keeps them even when the plugin is missing.
- **Format registry, 19 rows** (`crates/io/src/formats.rs`): design (`.sc`/`.solidcraft`/`.solvecraft`/`.json`), STEP and IGES import+export, FreeCAD `.FCStd` and Rhino `.3dm` import, STL/3MF/OBJ import+export, glTF import only, GLB export only, PLY/XYZ/PTS point-cloud import, URDF export, DXF drawing import and current-view DXF export, SVG drawing import. Commercial codecs are not compiled in (`Cargo.toml`: cadmpeg without f3d/sldprt/inventor/catia/creo/nx/sat).
- **Commands**: `file.save` (`format: container|json`, `compression: fast|compact`, optional geometry `cache`, optional display `preview`), `file.export` (`step|stp|iges|igs|3mf|3mf-tagged|stl|stla|obj|glb|urdf|json`, with quality/mesh options; `lay_on_print_faces: true` lays each body on its print face for STL/3MF), `file.export_step`, `file.export_stl`, `file.export_3mf`, `file.export_obj`, `file.export_urdf`, `file.save_mesh`, `file.export_view_dxf`, `file.send_to_slicer`/`file.slicers` for installed slicers, and `file.import_cache_clear` for the reused-import cache. GLB export now keeps an assembly's structure: each component/occurrence is a named, movable node.
- **Forward compatibility**: format 55 reads every earlier format; 0.40.0/0.40.1 open a 0.41 file with a warning and keep what they cannot read; 0.30.1 and earlier refuse it. A file whose format number is newer than the build opens with a warning, reads what it can and keeps the rest on save (`crates/format/src/newer.rs`).
- **Drawings are groundwork only**: `.scdwg` has a document model and a container reader/writer (`crates/doc/src/drawing.rs`; `crates/io/src/design/drawing.rs`; `DRAWING_EXT` in `crates/io/src/lib.rs`), but nothing in the app or engine opens one — there is no `drawing.*` command, and the drawings milestone is still listed as unmerged in `ROADMAP.md`. The Insert Drawing dialog places SVG and DXF files on a sketch, not `.scdwg`.

### Platform and packaging

- Desktop app (egui) with multiple designs as tabs (tabs show the saved file name; the window title shows the design and its unsaved state); the same engine runs as a WebAssembly browser app (`apps/solidcraft-web`, `docs/browser-api.md`), a headless CLI, an MCP server and the plugin host (`docs/architecture.md`). Design and Render share one docking system now; saved panel layouts still work and Classic is still an arrangement.
- macOS is signed with a Developer ID and notarized (`spctl` on the installed bundle: "accepted, source=Notarized Developer ID"). Windows builds now carry SignPath-provided code signing; until the production certificate is in place SmartScreen may still warn (choose **More info** → **Run anyway**) (`README.md` Download).
- Saves show progress and can be cancelled until the file is replaced. Agent commands compute beside the window on new installs (`agent_off_thread: true`), each waiting command is its own cancellable row in the operations panel, and the agent's pointer stays on what it picked when you turn the view.
- Headless screenshots use a GPU device and fall back to a CPU rasterizer, saying which (`docs/mcp.md` `screenshot`). The desktop app also hosts an agent **Assistant** panel for ACP/API agents; desktop only (`docs/agent-chat.md`).

## Known limitations and not-implemented

- **Early but usable for simple parts** — the project's own words. The oracle covers 90 simple reference parts; complex multi-body workflows are not proven to that standard (`docs/oracle.md`; `docs/capabilities.md`).
- **One planned command**: `surface.fillet` refuses with issue #769. Any other tool you cannot find in `solidcraft-cli commands` / `describe_command` should be treated as absent.
- **Plugins are experimental**: desktop/headless only; no browser execution, automatic download/update, custom panels or plugin-defined feature types; a 0.x capability may break between minors; the runtime embeds no network and no WASI. Installing/running is always an explicit, user-reviewed action.
- **Drawings are milestone work**: `.scdwg` has a document model and reader/writer, but no UI or command opens it; the Insert Drawing dialog places SVG/DXF on a sketch only (`ROADMAP.md`; `crates/ui-egui/src/dialogs_insert_drawing.rs`; `crates/io/src/design/drawing.rs`).
- **No CAM**: Send to Slicer exports to a slicer; it does not generate toolpaths (`ROADMAP.md` "Manufacturing / CAM").
- **Kernel limits unchanged**: G2 fillets only on straight edges between planar faces with planar ends; some coincident curved booleans can still fail; mass properties come from fine tessellation, not exact integration (`ROADMAP.md` "Known limitations"). 0.41 fixed the near-tangent mitre regression and the STEP export orientation, not these boundaries.
- **Format 55 is forward-only for 0.30.x**: 0.40.x opens it with a warning and preserves what it cannot read (`crates/format/src/newer.rs`); 0.30.1 and earlier refuse it.
- **The control channel is off on a new install** and for preference files saved before the setting existed (`crates/ui-egui/src/prefs.rs`: `agent_control: bool = false`, test `agent_control_is_off_unless_saved_on`). Enable it in Preferences ▸ Assistant ▸ Agents through MCP ▸ "Let AI agents connect", or launch with `--control PORT`. A bridged `solidcraft-cli mcp` starts anyway but every call fails with `no SolidCraft app is listening at HOST:PORT` until the channel is enabled.
- **MCP file access is fenced**: save/open/export/screenshot only inside the design's folder, folders the agent opened or saved in, the recovery folder, the server scratch folder, and `--allow-path` entries; hidden folders and files are out of reach. A `save` elsewhere is an error — ask the user to add `--allow-path`, do not route around it through the control port (`docs/mcp.md` "Which files the agent can reach"). The same fences apply to `plugin.install`/`plugin.run` package paths.
- **Exports from 0.40.x can be inside out**: 0.41.0 fixed STEP export so solids no longer have faces pointing into the material (#15175). If you rely on a STEP file written by 0.40.x, re-export it with 0.41.0 before trusting volume or orientation in another program.
- **Doc drift to discount**: `README.md`/`docs/capabilities.md` say "75 of 76" oracle parts (the generated `docs/oracle.md` says 90/90); `docs/features.md` is six commands behind the registry; `docs/control-protocol.md` says "off by default" in one place and its launch table still says the setting is "on (the default)" (and that old preference files load it on — the test says the opposite); `docs/mcp.md` and the `skill_reference` description list `reporting`/four skills where the code embeds `sheetmetal`/five. `docs/oracle.md` still carries the note that case 95's centre-of-mass reference needs a replay.

## How to operate

- GUI: `open -a SolidCraft`; `solidcraft --sample` opens a sample part. App flags: `--control PORT`, `--theme-file FILE`, `--max-file-size SIZE`, `--safe-mode`, `--crash-log`, `--version`, `--help` (`apps/solidcraft/src/main.rs`).
- The CLI ships **inside the app bundle** at `Contents/MacOS/solidcraft-cli`; package installs and the app's Help ▸ Install solidcraft-cli put it on `PATH`, but a given Mac may not have it there — use the bundle-relative path when `command -v solidcraft-cli` is empty.
- First run of the control channel: Preferences ▸ Assistant ▸ Agents through MCP ▸ **Let AI agents connect** (default off). It takes effect immediately, closes/opens the port and rewrites the token file (`crates/ui-egui/src/control_switch.rs`). `--control PORT` and `SOLIDCRAFT_CONTROL_PORT` work regardless of the setting.
- Headless loop (verified flags):
  ```sh
  solidcraft-cli commands                                   # the registry as JSON (642 ids)
  solidcraft-cli exec solid.box '{"length":40,"width":30,"height":20}'
  solidcraft-cli run examples/bracket.json --out bracket.step
  solidcraft-cli run build.json --save part.sc              # .sc container (--save = file.save_as)
  solidcraft-cli eval part.sc                               # measurements as JSON
  solidcraft-cli script part.sc --out rebuild.json          # history as a script
  solidcraft-cli snapshot part.sc --out shot.png --view iso
  solidcraft-cli render part.sc --out render.png --samples 64
  solidcraft-cli oracle tests/oracle/01-box                 # needs case directories
  solidcraft-cli kernel-cases tests/kernel-cases/continuity/g0-box-edge-crease
  solidcraft-cli mcp --headless --in part.sc
  solidcraft-cli mcp setup                                  # register with your client
  # plugins, explicitly: plugin.inspect (folder) -> review -> plugin.run (same hash), in a script
  ```
  `--out` runs `file.export` (STEP/STL/3MF/OBJ/JSON by extension; `--out x.sc` writes plain JSON), `--save` runs `file.save_as` and writes the `.sc` container. `snapshot` takes `--out` (there is no `-o`). `oracle` and `kernel-cases` refuse with no case directory. `run` accepts a design or STEP as `--in` and writes `--out`/`--save`; a failed feature fails the run unless `--allow-errors`. `--json-out FILE` writes the JSON those commands print, as plain UTF-8.
- Bridged MCP (watch the agent model): turn the control channel on (or `solidcraft --control 7878`), then `solidcraft-cli mcp` finds the app from `control/current.port`; or `solidcraft-cli mcp --connect 127.0.0.1:7878`. A bridged server starts before the app and retries on the first call.
- Token/discovery live in the platform data folder's `control/` directory, per the table in `docs/control-protocol.md` (macOS uses the Application Support family). `SOLIDCRAFT_CONTROL_DIR` moves it; `SOLIDCRAFT_CONTROL_TOKEN` supplies a known token.
- Web: `solidcraft.io/app` runs the same engine in the browser; pages drive it through the API in `docs/browser-api.md`.

## Working with an AI agent

- **Model like a person**: `list_commands` → `describe_command` for the typed contract → `execute` per step, or `batch` for a stage. Sketch ids from `created:` are stable, so `sketch.*` → `sketch.dimension` → `solid.extrude` → `solid.fillet` can chain without re-picking.
- **Read `skill_reference` first** for enclosures, brackets, plates, flanges and mechanisms. Its discipline (paraphrased): work the part out as numbers first; place it on the origin; use one `batch` per stage; verify every stage with `measure` against values you computed; keep risky steps in their own batch; pass `verbose: false` in large designs; edge picks snap to the nearest edge (compute exact midpoints); a cut that misses can still report success.
- **Use `check_parameters`** to try parameter values without keeping them (one checkpoint, one rebuild, restore); use `inspect.parameter_variants` to compare named value sets. `model.mesh` reads a body's evaluated mesh (chord tolerance default 0.05 mm, capped at 8192 vertices / 16384 triangles) for inspection without changing the design.
- **Prepare and verify files**: scripts are plain JSON — generate them, diff them, keep them in git. `script` extracts an existing design's history; `eval` and `inspect_design`/`measure` verify geometry; `compare_picture` checks a model outline against a reference image; `screenshot`/`ui.render` give visual evidence. To inspect or repair a `.sc`, use `file.save {format: "json"}` for the plain document or `script` for the history rather than editing the container's ZIP members by hand.
- **Undo is a tool**: `undo`/`redo` over MCP; `batch` rolls back completed steps on failure by default, and a failed command leaves the design unchanged — a failed `execute` needs no cleanup.
- **Respect the fences**: the MCP server's folder rules are a security boundary; ask the user to add `--allow-path DIR` rather than saving through another surface. Read the token file or use `SOLIDCRAFT_CONTROL_TOKEN`; never hard-code a token. The plugin package folder is fenced the same way.
- **Plugins are never implicit**: use `plugin.list`/`plugin.inspect` to answer questions about what is installed or what a package asks for; only `plugin.run` (with the exact approval hash the user reviewed) executes code, and only when the user asked for that plugin. Do not install a plugin to "try it". Over the desktop, one `plugin.run` per request — batches and scripts refuse it.
- **Prefer commands to pixels**: `ui.*` input injection exists for dialogs and picks that no command covers, and `ui.agent_cursor` makes it watchable, but pixel-driving is slower and more brittle than an id from `commands`. The Constrain dialog and the docking/plugin-menu UI are examples of UI over existing commands — a command path exists for the model changes they make.
- **Slow agent work is off the window thread by default** on new installs: a long command shows in the operations panel as its own cancellable row, and `ui.operations` reports the queue `next` and per-row `percent`. A timed-out control request is still running (see "Limits"), so cancel or `control.pending` it instead of blind-retrying.
- **What not to attempt**: assuming commercial-CAD parity (clean-room, independent); expecting proprietary formats (SolidWorks, CATIA, Creo, NX, Inventor, ACIS SAT are not compiled in); promising `surface.fillet`, a drawing workspace, CAM or a general plugin platform; driving the GUI before checking whether a command exists; installing or running plugins without explicit user review.

## Verification protocol

1. **Round-trip in a scratch design first**: new design → build → `save part.sc` → `open` it back → `export` STEP → re-import or `inspect_design`; compare volume, area and bbox with `measure` before trusting the chain. Check the STEP's orientation/volume sign in a second tool — 0.40.x wrote solids inside out and 0.41.0 fixes it, so a stale export may read negative.
2. **Use the oracle and kernel rig as harnesses**: `solidcraft-cli oracle tests/oracle/<case>` replays recipes with expected values; `kernel-cases` runs the kernel regression rig. Model your own checks the same way (recipe/script plus expected values in git).
3. **Never trust a silent export, a silent cut or a "status 1001"**: `export` says what it wrote — re-open and re-measure. A cut or hole that leaves the volume unchanged has missed even when it reports success (`skills/solidcraft-modeling/SKILL.md`). 0.41.0 names the reason a fillet/chamfer failed instead of status 1001; read it.
4. **One design per session, save between phases**: `new_design`/`open`/`save`; keep scripts in git so any phase is replayable. `script` recovers a history you did not keep.
5. **Re-verify after updates**: compare `solidcraft --version` with this skill's pin (v0.41.0) and run `solidcraft-cli commands`; the registry is the contract. Design format 55 opens in 0.40.x with a warning, but 0.30.1 and earlier refuse it.
