# TextureCraft

## Overview

TextureCraft is an open-source (MIT OR Apache-2.0), pure-Rust 3D texture-painting application — the ArtCraft suite's clean-room answer to Adobe Substance 3D Painter (the repo aims for 1:1 parity with that texturing workflow, with better performance, a smaller footprint and every feature drivable by agents — `ROADMAP.md`). Its own weighted estimate is **≈94%** done across 11 areas (`ROADMAP.md` "Honest parity estimate (2026-11-04)"; baking was lowered to 90% pending reference-asset validation). It runs natively on macOS (universal, signed, notarized), Windows, Linux, FreeBSD and in the browser via WebAssembly/WebGPU-or-WebGL2 (`README.md`, `ROADMAP.md` Platforms). Source: GitHub `storytold/texturecraft`. The workspace is 11 crates (`automation`, `bake`, `compose`, `core`, `engine`, `formats`, `geom`, `paint`, `render`, `texel`, `ui-egui`) plus three apps (`apps/texturecraft`, `apps/texturecraft-cli`, `apps/texturecraft-web`).

The one governing idea: **everything is an engine command with a stable id** (`layer.add.fill`, `bake.run`, `edit.undo`, … — `docs/control-protocol.md`), and the UI, `texturecraft-cli`, the JSON control channel and the MCP server all run the same registry (**172 unique command ids** at v0.4.0; the generated menu doc counts **58 of 58 menu items live**, `docs/parity.md`, regenerated by `TC_UPDATE_PARITY=1 cargo test -p texturecraft-ui-egui parity`). Programmatic calls never open dialogs; `session.inspect` reports every layer, mask, effect, fill source, per-tile `bakeEnabled` flag and painted tile count so an agent can verify work without screenshots.

### Painting, layers and materials

- **Paint on the 3D mesh or the 2D UV view**: brush (size/flow/stroke-opacity/spacing/hardness/angle/follow-path, jitters, tangent or camera alignment, angle fade, backface culling, lazy mouse, X/Y/Z mirror + radial symmetry, pen pressure), eraser, **projection with image stencils** (hold S), polygon fill (triangle/UV-island/mesh), **path and lasso fill**, **particle brush**, smudge, clone (V + click sets source), colour picker, Shift+click straight lines, **quick mask** (Y), **geometry decals** and **text** (`docs/features.md` §Paint in 3D). **67 procedural brush alphas** (31 generated shapes + 36 stencil glyphs, `crates/paint/src/alphas.rs`) plus any imported image; **18 brush presets** in three groups, with user presets saved as `.tcbrush` (`crates/paint/src/presets.rs`, `crates/engine/src/brush_preset_cmds.rs`).
- **Layer stack**: paint, fill, folder and **instance** layers; **32 blend modes per channel** with per-channel opacity; white/black/painted masks, **mask with height**, smart masks, generators; **31 library filters** (`crates/engine/src/filter_lib.rs` `FILTERS`: adjustments, blur/sharpen/high-pass, bevel, glow, edge detect, warps, mosaic, baked lighting, four material finishes); **geometry masks** (a layer visible only on chosen mesh parts); anchor points; copy/paste across texture sets, flatten, save layers/folders as `.tcmat` smart materials. All **24 smart masks** are procedural and expose their preset id: `mask.smart.list` to enumerate, `mask.smart.apply {name, layer?}` to replace a layer's mask; the six new ones are `snow_top`, `moss_ground`, `rust_cavities`, `edge_scratches`, `dirt_streaks`, `occluded` (`crates/engine/src/smart_masks.rs`).
- **Bundled library**: **72 procedural materials and 21 smart materials** (93 shelf entries), **24 smart masks**, **23 procedurals**, **6 procedural environments** plus imported HDR/EXR panoramas (`crates/engine/src/materials.rs` `MATERIALS`, `crates/core/src/layer.rs` `ProceduralKind`, `crates/core/src/project.rs` `ENVIRONMENTS`). A shelf material can be dropped on the texture set under the cursor, and hover shows a large preview (`crates/ui-egui/src/shelf.rs`). **MaterialCraft materials**: `material.load` accepts a `.mcmat` portable material or `.mcraft` package as a fill layer, re-cooked through MaterialCraft's command line with the set's baked mesh maps (`docs/control-protocol.md` §MaterialCraft materials, `crates/engine/src/link_cmds.rs`).
- **Channels**: 21 `Channel` variants per texture set — base color, metallic, roughness, height, normal, emissive, opacity, AO, specular level, specular, glossiness, clear coat weight/roughness/normal, sheen weight/colour/roughness, anisotropy level/angle, subsurface scattering weight, transmission (`crates/core/src/channel.rs` `pub enum Channel`). Texture sets 128–8192 px, **UDIM/UV tiles** with per-tile working resolution and `$udim` export.
- **Viewport**: PBR with IBL, ACES/linear tone mapping, depth of field, displacement, 4× MSAA + idle temporal accumulation, channel/mesh-map/mask/UV-checker views, saved cameras (also imported from glTF/FBX/COLLADA/USD) with **Ctrl+1…9 bookmarks** (`camera.bookmark1`…`9`), top-bar layout and perspective/orthographic dropdowns, a draggable 3D/2D divider, and **Rendering mode (F10)** — a progressive path tracer on GPU compute (the repo claims ~25× CPU) or CPU, with environment importance sampling and an edge-aware denoiser.

### Bake and export

- **Bake mesh maps** — **10 baked maps**: normal, world-space normal, ID, ambient occlusion, curvature (also from the normal map), position, thickness, height, bent normal, opacity (`crates/core/src/bake/baked_map.rs` `BakedMap::ALL`). v0.3.0 also had `ColorMap` and `WorldDirection`; both are gone at v0.4.0, so do not request `colorMap`/`worldDirection` any more. GPU ray tracing (the repo claims ~12× the CPU path) or all CPU cores; high-poly meshes with cage, frontal/rear distances, average normals, match by mesh name; 2D cage and skew paint (`bake.cage.paint`/`bake.cage.reset`, `bake.skew.*`); mesh maps can also be imported as images (`textureSet.meshMap.set`). Fresh settings default to 64 AO rays, cosine distribution, 180° spread and linear AO attenuation (`crates/core/src/bake/ray_settings.rs`, `crates/core/src/bake/ambient_occlusion_attenuation.rs`).
- **Per-set bake settings**: each texture set owns a nested `BakeSettings` (common resolution/antialiasing/dilation plus per-map parameters). `bake.settings` reads or edits it: `model` replaces the whole settings object, `patch` changes only the named fields (nested `maps.ao.parameters.rays.rays`, …; `null` clears optional fields), `preserveEnabled` keeps the set's Include-in-Bake flag, and flat parameters (`resolution`, `antialiasing`, `dilation`, `ao`, `thickness`, `bentNormal`, `rays`, `maxDistance`, `curvatureMethod`, `positionMode`, `maps`, `enabled`, …) apply last. It returns `[{ts, settings, model}]` per targeted set (`crates/engine/src/bake/mesh_map_command.rs`). `bake.run` takes the same parameters plus `ts`/`cpu` and returns `{baked, tracer}`; **there is no auto-rebake at v0.4.0**.
- **Per-tile bake selection**: `bake.tile.set {ts?, tile: 1002, enabled: false}` excludes one UV tile; `session.inspect` reports each tile's `bakeEnabled`; excluded tiles keep their previous baked pixels (`crates/engine/src/bake/tile_command.rs`).
- **Export presets**: `Document channels + Normal + AO`, `glTF PBR Metal Roughness`, `Unreal Engine (Packed)`, `Unity HDRP (Mask Map)`, `Unity Standard (Metallic Smoothness)`, `Blender (Principled BSDF)`, `Godot 4 (ORM)`, `OpenPBR (separate maps)` (coat/fuzz/anisotropy/transmission/subsurface maps), `Separate maps`, `Mesh maps` — **10 built-ins** plus **user output templates** (per-channel packing, converted maps, JSON shareable) (`crates/formats/src/presets.rs`). Texture formats: PNG, JPEG, TGA, TIFF, BMP, WEBP, EXR, HDR — **depth is per format** (PNG/TIFF 8 or 16, EXR 16 or 32 float, HDR 32, the rest 8), plus UV padding, size override, OpenGL/DirectX normals, colour-space conversion of colour maps and `$udim` tiles (`crates/formats/src/export/mod.rs`). Mesh export to OBJ (+MTL and maps), textured GLB (clear coat + sheen) and USD (clear coat), **5 formats** (`crates/engine/src/file_cmds.rs` `MESH_EXPORT_FORMATS`).

## Known limitations and not-implemented

At v0.4.0, do not assign these:

- **No auto-rebake.** The `bake.autoRebake` commands of v0.3.0 were removed. After changing `bake.settings`, the mesh, high polys or the skew/cage paint, run `bake.run` yourself; nothing bakes in the background.
- **Old projects are recovered, not converted.** v0.4.0 writes `format_version: 2` (v0.3.0 wrote 1); older files load, newer files are refused (`crates/core/src/project.rs` `FORMAT_VERSION`, `crates/formats/src/project_file/mod.rs`). A `.tcraft` whose bake settings or baked map entries no longer deserialize opens with defaults for the unreadable fields (and drops unreadable maps, including the removed `ColorMap`/`WorldDirection`) under a log warning (`crates/formats/src/project_file/recovery.rs`); re-bake to restore those maps. Baked pixels of older UDIM projects keep their old layout — the app does not convert baked pixels.
- **`mesh_reimport` does not preserve paint by default.** Pass `preserveStrokes: true` (MCP/command) to re-project painted pixels where UVs changed; without it the mesh is replaced with no re-projection.
- **The macOS app bundle contains only `TextureCraft`** — no `texturecraft-cli`. Get the CLI from the release's separate macOS CLI zip (`packaging/macos/package.sh`), or build it. `Contents/MacOS` verified.
- **Pen tilt is not exposed** by the windowing layer (`ROADMAP.md` M2).
- **HDF5 Alembic is unsupported** (Ogawa only) and Alembic animation reads the first sample only (`ROADMAP.md` Project and files gaps).
- **Sheen and anisotropy do not export through USD** (UsdPreviewSurface has no such inputs; GLB and OpenPBR maps carry them) (`ROADMAP.md` Export gaps).
- **The bundled asset library is smaller than the reference app's**, and translations have had no native-speaker review (`ROADMAP.md` Materials/UI gaps).
- **Hardware ray tracing is not used** (compute shaders only) (`ROADMAP.md` Viewport gaps).
- The CLI/control/MCP surfaces run commands with defaults and never open dialogs; only `ui.menu.invoke` behaves like a click (`docs/control-protocol.md`). Bridge mode cannot touch files itself — the app does — so path tools are unavailable there and `project_save` without a path becomes File › Save.

## How to operate

- Headless one-shot (positional order: input first; `run` takes the command id then optional JSON params, with `-o` last):
  `texturecraft-cli new builtin:material_ball out.tcraft` → `texturecraft-cli bake out.tcraft --resolution 1024 --maps ambientOcclusion,curvature` → `texturecraft-cli export out.tcraft textures/ --preset "glTF PBR Metal Roughness" --format png` → `texturecraft-cli render out.tcraft preview.png --size 1024x1024` (`apps/texturecraft-cli/src/main.rs`; `docs/features.md` §Built for agents).
- Script a session: `texturecraft-cli run project.tcraft layer.add.fill '{"color":"#336699","roughness":0.2}' -o result.tcraft` — commands are the same ids `commands --filter` lists. A batch script is a step list or `{"open", "steps", "save"}` with paths relative to the current directory.
- Edit bake settings precisely: `texturecraft-cli run out.tcraft bake.settings '{"ts":"all","patch":{"maps":{"ao":{"parameters":{"rays":{"rays":128}}}}}}'`; bake with overrides via `texturecraft-cli run out.tcraft bake.run '{"ts":"all","maps":["ambientOcclusion","curvature"],"resolution":2048}'`. Exclude a tile with `bake.tile.set {"tile":1002,"enabled":false}`.
- Cameras: `camera.add {"name":"Hero"}` saves the current view; `camera.bookmark1`…`9` (or `camera.select {name}`) jump to it; `texturecraft-cli render scene.tcraft hero.png --camera Hero` renders through it.
- Drive the live app: on macOS `open -a TextureCraft --args --control 7878` (the bundle has no CLI; `--args` apply on a fresh launch, so quit a running copy first), or launch the `texturecraft` binary with `--control 7878`; read the token from stderr or `<temp>/texturecraft-control-7878.token` (or set `TEXTURECRAFT_CONTROL_TOKEN`), send the `auth` line, then `command.run`/`session.inspect`/`viewport.screenshot`.
- Agent flows: `claude mcp add texturecraft -- texturecraft-cli mcp --read-root . --write-root .` (or a `.mcp.json`); bridge to the running app with `--bridge 7878`. Typical run: `project_new` → `command_run layer.add.fill` → `bake` → `command_run mask.add.black` → `command_run effect.add.generator {"generator":"edgeWear"}` → `session_inspect` → `viewport_render` → `project_save` → `textures_export` (`docs/control-protocol.md`).
- Verify without screenshots: `session.inspect` / `session_inspect` return project, mesh, texture sets (including each tile's `bakeEnabled`), layer stack, tool, camera, display, history; `bake.settings` returns the effective settings per set; `debug.frames` reports frame timing after a scripted stroke.
- `TEXTURECRAFT_NO_PREFS=1` isolates a scripted run from the user's saved layout/settings.

## Working with an AI agent

- Register the MCP server per `docs/control-protocol.md` (headless with roots, or bridged). In bridge mode the app reads and writes its own files, so path tools are unavailable and `project_save` without a path performs File › Save.
- Every tool call maps to one control method; `command_run` accepts any engine command id except the refused `file.*` set and path-taking commands. `command_list {filter}` is the discovery contract.
- Painted strokes and renders share one pixel space: coordinates for `paint_stroke` can be read off a `viewport_render` image at the default 1280×800.
- Baking is GPU-first with `cpu: true` fallback; use `bake.settings` `patch` for one parameter instead of hand-building a whole model, and always pass `ts` when more than one texture set must change.
- For reusable material libraries use the `.tcmat` round trip (`material_save`, then `material_load` above the selection); `material_load` also ingests MaterialCraft `.mcmat`/`.mcraft` packages.
- Treat a recovered project as untrusted until re-baked: check the log for the recovery warning, run `session.inspect`, re-bake the affected sets, then re-export.
- Reimport a changed mesh with `mesh_reimport {"path":"model.glb","preserveStrokes":true}` and confirm `session_inspect` reports `modified: true` before saving.

## Verification protocol

1. `texturecraft-cli commands --filter <text>` — the live registry for the build in front of you; never trust any static number in this skill over it.
2. `session.inspect` after each mutation — layer stack, mask targets, fill sources, tile `bakeEnabled`, baked maps, `modified` flag and painted tile counts.
3. Bake: `bake.settings` for the effective per-set model, `bake.run` for its `{baked, tracer}` result; `session.inspect` confirms the baked maps per texture set. Baked output is per-set and per-tile — check the tiles you meant to include.
4. Exports: `textures_export` returns the written files; check names, packing, per-format bit depth and UDIM tiles against the preset.
5. Frame-loop work (recordings, perf): `debug.frames` before/after; `strokeEnd` in its result names the frame a scripted stroke committed.
6. Re-derive counts at v0.4.0: engine registry **172**, MCP `tools/list` **22**, serve `methods` **17**, control methods **13**, CLI `--help` **10 subcommands**, menu parity **58/58** (`docs/parity.md`).
